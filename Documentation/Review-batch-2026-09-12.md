### 2. resolvingOpacity traps (index out of range) on a run whose offsetX a leading-edge cut made negative

**`Sources/TUIkit/Rendering/OpacityResolution.swift:361`** — severity high, finder confidence high

**Mechanism.** `faded(_:covering:…)` builds `let columns = run.offsetX..<(run.offsetX + run.width)` with no clamp, one line after `let prefix = String(repeating: " ", count: max(0, run.offsetX))` — which shows the author knew `offsetX` can be negative here. `columns` is handed straight to `FrameBuffer.blendedSpan(source:destination:columns:…)` (OpacityBlend.swift:63). That function allocates `sourceCells = cells(in: source, through: columns.upperBound)` — `[RowCell?](repeating: nil, count: max(0, width))`, i.e. indices 0..<upperBound (OpacityBlend.swift:430) — then starts its walk at `var column = columns.lowerBound` (line 88) and immediately does `sourceCells[column]` (line 101). With a negative lowerBound that is a negative array index, which traps. The destination side of the same loop IS guarded (`behindCells.indices.contains(behindColumn)`, line 115, with a comment saying "a negative shift is legal — `composited` accepts one"); the source side is not. The sibling caller `rebuild` (line 174) is safe only because it clamps with `let start = max(0, first)`.

**Failure.** `ScrollView { HStack(spacing: 0) { Spinner(); Text("ABCDEFGH") }.opacity(0.5).offset(x: -3) }.frame(width: 12, height: 4)`.
