## `7cd7c15a` — interrupted and partial terminal I/O · `have`

The one commit in this branch with a defect worth hunting for, and both halves
are already closed here, each with its rationale in place:

- **Writes.** `Terminal.writeAll` loops on the unwritten tail and retries on
  `EINTR`. The comment records what it replaced: `if result <= 0 { break }`
  treated a signal (SIGWINCH, SIGCONT, SIGTSTP) landing mid-flush as a hard
  error and abandoned the rest of the frame — a truncated frame, or a terminal
  left half-restored mid-teardown.
- **Reads.** `readSource` retries only on `EINTR` and passes everything else
  through unchanged, so the benign `EAGAIN` of a non-blocking descriptor is not
  mistaken for data.

`SystemClipboard` carries the same treatment. The related pipe-buffer deadlock
class is covered in `PR-47.md` and `PR-49.md`.

## Two `defer`s

- **`831b0bd2` — surface terminal failures from the runtime.** Ours swallows a
  hard write error and keeps going. The failure that would expose it is narrow —
  stdout dying while stdin stays open, which for a TTY app usually means both
  are gone and the read loop exits anyway — but "render forever into a dead
  descriptor" is a real end state. Worth doing; nothing forces it now.

- **`cfb6afba` — deterministic shutdown test.** A genuine coverage gap:
  `MockTerminal` already tracks `isRawModeEnabled`, `isCursorHidden` and
  `isInAlternateScreen`, and **nothing asserts** that teardown restores all
  three. There are *two* restore sites that must agree — `cleanup()` and
  `suspendUntilContinued` (SIGTSTP) — which is exactly the shape that drifts.
  Not written now because both are `fileprivate` on the `App` extension, so a
  unit test needs a source change first; the alternative is a PTY probe
  asserting the quit path emits `ESC[?25h` / `ESC[?1049l` and restores termios.
  Low urgency: a regression here strands the user's shell in raw mode, which is
  the loudest possible failure.
